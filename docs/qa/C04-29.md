# C04-29 작업 고르기 (2026-10-21)

## 바뀐 것
- 작업 추가의 공종 칸 → `작업 고르기` 모달(업종 → 업무분야 → 작업). 폼 안의 겹친 dialog라 체크 상자가 그대로 전송된다. 좁은 화면(≤760px)은 한 단씩, 뒤로 버튼.
- 날씨 기준 없는 작업은 폭염만 판정(D-085).

## 자동 검증
- `scripts/check.py`: ruff·format·mypy·pytest 모두 통과.
- 새 테스트: 법령 별표 1 표와 업종·업무분야 이름·순서 대조, 기존 판정 공종 이름 유지, 작업 저장(중복 체크는 한 건), 자주 쓴 작업 순서, 업종 표시 순서, 날씨 기준 없는 작업의 카드(판정 전 단계 없음·폭염 확인 필요·풍속 기준 미적용·폭염 진행이면 진행).

## 브라우저 확인 (Edge, 시연 계정 pm@demo.gongon.test, 현장 38, 포트 8001 임시 서버, 저장하지 않음)
- 1440px·390px: 모달 열기 → 철근ㆍ콘크리트공사업(업무분야 1개라 바로 작업 칸) → 벽체 철근·콘크리트 타설 → 구조물해체ㆍ비계공사업 이동식 크레인 → 철강구조물공사업의 이동식 크레인이 함께 체크됨 → 선택 완료. 칩 3개, `작업 3건 추가`. 단계: 열기 1 → 업종 3 → 뒤로 1. 가로 넘침 없음, 스크립트·콘솔 오류 0.
- 확인 중 고친 문제 2건: ① 업종 숫자 배지가 기존 `[data-count]`(추가 건수 문구)와 이름이 겹쳐 건수 문구가 배지에 쓰일 수 있었음 → `data-wcount`. ② `.wpick__list`·`.wpick__kinds`의 `display: grid`가 `hidden`을 덮어 모든 업무분야·작업이 한꺼번에 보임 → `[hidden]`에 `display: none`.
- 개발자 요청 반영: 작업 고르기 아래 요약 문장(`2개 · 가스 배관, 난방 배관`) → 개별 토큰, 토큰마다 ×로 하나씩 빼기(폼 칩도 같음). 1440·390px에서 × 클릭 시 그 작업의 모든 칸 체크가 풀리고 건수가 3→2→1건으로 바뀜, 오류 0.
- 홈 날 패널 묶음 펼치기: 시연 현장에는 같은 날 같은 작업 2건 이상이 없어 개발 DB를 바꾸지 않고, 테스트 DB 시나리오(철골 2건 중 1건 중지 검토, 벽체 철근 2건)의 홈 HTML을 Edge에 띄워 확인. 1440·390px: 중지 검토 묶음은 처음부터 펼침, 다른 묶음은 눌러 펼침(하위 4줄), 칸 숫자 진행 3·중지 검토 1(작업마다), 가로 넘침 없음. 390px에서 `2건` 표시가 이름 위로 밀리던 배치를 같은 줄로 고침. (콘솔의 FLASH_PARAMS 중복 오류는 로그인 화면 위에 HTML을 덮어쓴 확인 방식 때문이며 실제 화면 문제 아님)
- 업체별·위치별 묶기(Edge, 시연 계정, 포트 8001 새 서버): 홈 날 패널 업체 줄 `우진철강`·위치 줄 `102동 2층`, 작업 일정 달력 칸 `N건`+`!`, 날 상세 업체별 `평화가설 · 협력업체`. 1440·390px 가로 넘침·스크립트 오류 없음. 개발자 화면(포트 8000)에서 업체 칸이 비어 보인 것은 서버가 바뀐 파이썬 코드를 다시 읽지 않은 상태(템플릿만 새것)였음 → 서버 재시작 필요.

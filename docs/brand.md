# 브랜드 가이드: 공온

화면·알림·용어의 기준이다. 제품 범위는 총정리 §1~3, 현재 구현 상태는 plan을 따른다. 아래 변경 업무 용어는 신규 화면 설계안이며 기존 화면을 바꿨다는 뜻은 아니다.

## 1. 이름과 제품 설명

- 서비스 이름: **공온**(공사 + ON), 코드 식별자 gongon.
- 현재 설명: **공사 변경 뒤 필요한 일을 연결하고, 처리 결과까지 확인합니다.**
- 새 첫 화면의 질문: “변경 뒤 남은 조치는 무엇인가요?”
- 기존 “내일 공사 ON?”은 기상 화면의 질문이다. 전체 제품의 대표 질문이나 작업 허가 라벨로 확대하지 않는다.
- 상표·도메인 사용 가능 여부는 미확인. 외부 공개·상업 운영 때 확인한다.

## 2. 서비스 용어

| 용어 | 뜻 | 적용 |
| --- | --- | --- |
| 변경 건 | 같은 작업 변경과 관련 조치를 묶는 기록 | 새 제품 중심 단위 |
| 변경 버전 | 어떤 변경 내용을 기준으로 행동해야 하는지 구분 | 재변경은 새 버전 |
| 후속 조치 | 담당자가 실제로 처리해야 하는 일 | 예약·출역·검측 요청 등 |
| 열람 | 사용자가 해당 내용을 열어봄 | 수락·수행 완료와 구분 |
| 완료 보고 | 수행자가 처리 내용·근거를 제출 | 검증 전 상태 |
| 검증 완료 | 지정 담당자가 해당 조치의 근거를 확인 | 공식 승인·전체 적합성 보증과 구분 |
| 전화 확인 기록 | 사용자가 외부 연락 내용을 대신 기록 | 상대방의 직접 응답과 구분 |
| 공온 판정 | 공종별 기상 판정 | 근거 모듈로 유지 |
| 공온지수 v2 | D-052의 규칙 기반 제품 설계값 | 기상 화면만, 확률·전체 준비도 아님 |

기상 판정 `진행 / 확인 필요 / 중지 검토 / 판정 불가`는 그대로 쓴다. 조치의 열람·응답·완료·검증 상태를 기상 판정 4단계로 표현하지 않는다. “공사 ON”을 작업 허가·확정·진행 판정의 별칭으로 쓰지 않는다.

## 3. 문구 원칙

- 행위와 남은 일을 직접 쓴다. 예: “펌프카 예약 변경 · 완료 보고 대기”, “변경 v2 · 필수 조치 2건 남음”.
- 계획 확정은 예약 변경 완료가 아니다. 예약을 바꾸지 않은 상태에 “예약 변경 완료”를 표시하지 않는다.
- “전송 성공”, “열람”, “수락”, “완료 보고”, “검증 완료”를 구분한다. 실패·미정·대체·이전 버전을 숨기지 않는다.
- 사용하지 않는 주장: 안전 보장, 자동 승인, 모든 영향 검토 완료, 취소로 모든 처리 원복, 검증되지 않은 비용 절감률.
- 기상 상세·알림에는 “최종 판단은 현장 책임자가 합니다.”를 유지한다.
- 초기 발송은 웹·미리보기다. 실제 카카오톡은 D-015 조건 충족 후 제공한다. 미리보기를 “발송됨”으로 표시하지 않는다.
- 기한·조치 양식·판정 기준에 출처가 없으면 미확인으로 표시하고 고객의 기준을 지어내지 않는다.

### 공온 말투 (2026-10-16, D-063)

- 화면 머리 설명에는 공온(마스코트 공온이)을 주어로 써서 서비스가 하는 일을 한 문장으로 말한다. 예: “공온이 오늘 현장 일정과 내일 준비를 한 화면에 모았습니다.”
- 끝맺음은 ‘-니다’로 통일한다. 공온이 하지 않는 일(승인·보장·자동 처리)을 공온의 행동으로 쓰지 않는다.
- 기상 판정 화면은 “공온 판정”이라고 부른다. “공사 ON?”은 기상 판정 화면(대시보드)의 질문으로만 쓴다.
- 메뉴는 핵심 4개(홈·작업 일정·변경·현장)이고, 공온 판정·판정 내역은 작업 일정의 하위 메뉴다.

## 4. 기존 기상 공온지수의 범위 (D-050·D-052·D-053)

현재 채택된 버전은 gongon-index-v2다. 수치·구간값은 제품 설계값이며 예보 정확도·작업중단 확률·안전도·프로젝트 종합 준비도를 뜻하지 않는다. 기존 7일 기상 화면 안에서만 사용한다. 새 점수 정의나 화면 확대는 별도 요구사항·결정이 필요하다.

규칙 기반·동일 입력과 버전의 동일 결과·근거 설명·누락 처리·판정 상한을 유지한다. D-053의 같은 날 예보 추정은 직접 비교와 구분한다. 기존 화면 설명과 실제 동작의 차이는 C04-1에서 검증하며 문구만 고쳐 구현을 완료했다고 처리하지 않는다.

## 5. 시각 요소 (D-045, 2026-10-08 개발자 피드백)
- 기준: 파랑·흰색. D-039의 구조(흰 카드, 강조는 작은 면, 판정 의미 색)는 유지하고 흑백·라임 대신 파랑 #1C60EF·흰색·남색을 쓴다.
- 아주 옅은 파랑 바탕 위 흰 카드로 구역을 나눈다. 파랑은 주 행동 버튼·선택 메뉴·내일(판정 대상) 표시에 쓰고 그 위 글자는 흰색이다. 넓은 선택 면은 옅은 파랑을 쓴다. 남색은 제목 글자와 중지 검토 요약·데이터 상태 카드처럼 강조할 면에만 쓴다.
- 판정 4단계 이름은 그대로다. 채도를 낮춘 의미 색을 쓰되 배지는 항상 점과 라벨을 함께 둔다: 진행 그린, 확인 필요 앰버, 중지 검토 레드 면에 흰 글자, 판정 불가 회색 점선. 현장 목록·구간은 판정 색 왼쪽 띠로 훑어 읽게 한다. 0건인 요약 타일은 흰 면으로 가라앉힌다.
- 달력: 오늘은 남색 배지, 내일은 파랑 배지, 선택한 날은 파랑 테두리와 옅은 파랑, 작업 기간 밖은 빗금으로 표시한다.
- 정렬·밀도: 입력/버튼 6px·내부 묶음 8px·패널 12px 모서리, 배지·태그·메뉴는 알약형.
- Pretendard 직접 제공. 제목 28~32px/600, 소제목 18px/600, 본문 14px/400. 전환 0.18초, 동작 줄이기 설정 존중.

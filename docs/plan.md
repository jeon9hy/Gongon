### S05 개선 대기 목록 (현재 기능 범위 안)
- 대상 날짜 판정 없음·오래된 수집 성공·수집 실패를 구분한다. 과거 성공을 최신 자료 확보처럼 표시하지 않는다. 최신성 기준은 공식 발표/제공 시각 확인 후 정한다.
- 휴대폰 첫 화면은 대상 날짜·검토할 현장/작업·행동 버튼부터 보여준다. 소개와 기술 정보는 아래로 내리고 메뉴에 짧은 글자 라벨을 검토한다.
- 주소 선택을 기본으로 하고 직접 좌표 입력은 보조 경로로 둔다. 검색 실패 시 입력값 보존·재시도 경로를 확인한다.
- 기준 미확인과 실제 현장 확인 사유를 구분한다. 판정 4종 이름은 그대로 유지한다.
- 완료 증거: 과거 자료만 있는 상태·판정 없음·수집 실패·성공 화면, 주소 검색 실패, 좁은 화면과 데스크톱 확인. 단순 스타일 변경에 구현 복제 테스트를 추가하지 않는다.

1. 인계·현재 작업·Git 차이 확인 → 이번 작업의 입력/출력·변경 파일·실패 조건을 짧게 확정.
2. 필요한 공식 레퍼런스만 조회 → 출처·버전·적용 범위·미확인 사항 기록(`docs/references.md`).
3. 한 사용자 흐름의 처리·저장·화면을 연결 → 실제 오류 위험 중심 관련 테스트 실행.
4. 작업 완료/커밋 전 `uv run python scripts/check.py` 한 번. 실패 수정 시 필요한 검사 재실행. skip은 통과로 기록하지 않는다.
5. 계획 상태·약 30줄 인계 갱신 → 해당 파일만 명시해서 Git 저장. 진행 중에는 기존 브랜치 유지, 새 작업은 저장소 브랜치 규칙 적용.

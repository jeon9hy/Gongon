# 운영자(admin) 웹앱 기획서 (Codex 작업용, 2026-10-17 초안)

대상: 이 저장소를 이어받는 Codex. `AGENTS.md`의 규칙(작업 ID 하나씩, 결정 기록, 마이그레이션, `scripts/check.py`)을 그대로 따른다. 이 문서는 **기획 초안**이다. 시작 전에 `docs/decisions.md`에 결정(D-0xx)을 남기고 `docs/plan.md`에 작업 ID(예: `A01`~)를 만든다. 아래 '확인 필요'는 개발자에게 묻는다.

## 1. 목적

공온을 운영하는 사람(개발자·초기 운영자)이 고객 현장 자료를 함부로 바꾸지 않으면서 다음을 할 수 있게 한다.

- 가입자·회사·현장·참여 상태를 찾아보고 문제를 해결한다(예: 소유자 없는 현장에 조정자 지정 — 지금은 `scripts/grant_site.py`로 한다).
- 서비스가 제대로 도는지 본다(예보 수집, 자동 판정, 오류).
- 효과 지표를 본다(D-070 R6: 요청→응답, 요청→완료 보고, 보고→검증 시간).
- 계정을 막거나 푼다(스팸 가입, 퇴사자).

하지 않는 것: 고객 대신 변경 확정·조치 처리·검증(현장 기록의 신뢰가 깨진다), 판정 기준 수치 수정(규칙은 `rules/*.yaml`과 원문 대조로만), 메시지 열람(대화방 내용은 운영자도 보지 않는 것을 기본으로 — 확인 필요).

## 2. 구조 (같은 앱 안의 기능 하나)

- 별도 앱·별도 저장소를 만들지 않는다. `app/features/admin/`에 router·service·schemas·templates를 두고 `/admin/...` 주소를 쓴다. 다른 기능은 그 기능의 `service`·`schemas`로만 부른다(`tests/test_import_boundaries.py`).
- 권한: `users.is_staff`(bool, 기본 false) 마이그레이션. 스태프가 아니면 `/admin` 전부 **404**(존재를 드러내지 않음). 스태프 지정은 처음에는 스크립트(`scripts/grant_staff.py --email`)로만.
- 감사 기록: `admin_audit`(actor, action, target_type, target_id, before/after 요약, reason, at). 쓰기 동작은 이유 입력 필수, 모두 기록. 기록은 지우지 않는다.
- 개인정보: 휴대폰 번호·연락처는 기본 가림(`010-****-5678`), '보기'를 누르면 이유를 받고 감사 기록에 남긴다.

## 3. 화면

| 화면 | 주소 | 내용 | 쓰기 |
| --- | --- | --- | --- |
| 개요 | `/admin` | 가입자·현장·활성 현장(7일), 오늘 확정 변경, 열린 조치·막힘·기한 지남 수, 최근 예보 수집·자동 판정 상태, 최근 오류 | 없음 |
| 사용자 | `/admin/users` | 검색(이름·이메일·번호), 회사, 참여 현장 수, 가입일, 번호 인증 상태, 마지막 로그인 | 비활성화·재활성화(이유), 세션 끊기 |
| 회사 | `/admin/organizations` | 같은 이름 회사 묶어 보기(D-066 중복 확인용), 사용자·참여 현장 | 병합은 하지 않음(확인 필요) |
| 현장 | `/admin/sites` | 현장 목록·작업 기간·참여 업체·조정자 수, 조정자 0명 현장 강조 | 조정자 지정(이유) |

| 수집·판정 | `/admin/jobs` | `forecast_runs`·`mid_forecast_runs`·`judgment_runs` 최근 목록, 실패 사유 | 다시 수집(이유) |

목록은 모두 페이지 처리(50건), 필요한 필드만 조회(N+1 금지, `docs/architecture.md`).

## 4. 디자인 (지금 웹앱과 통일)

- 같은 `base.html`·`gongon.css`·아이콘 매크로(`_macros.html`)를 쓴다. 새 색을 만들지 않고 `:root` 토큰(`--accent`, `--ink`, `--surface`, `--line-soft`, 판정 4단계 색)만 쓴다.
- 배치: 상단 앱 바 아래 **왼쪽 세로 메뉴(220px) + 오른쪽 본문**. 앱 바 오른쪽에 '운영' 표시(알약, `--ink` 바탕). 일반 화면으로 돌아가는 링크.
- 숫자 요약은 홈 내일 카드의 지표 3칸(`.kpis`/`.kpi`, 큰 숫자 + 얇은 막대 `.meter`) 모양을 그대로 쓴다.
- 목록은 홈 작업 목록(`.jobs`/`.job`)처럼 줄마다 열 너비를 고정한 표 모양, 상태는 알약(`.pill--ok`/`.pill--warn`).
- 입력은 모두 **가운데 모달**(`dialog.modal` + `.modal__box`, 머리·아래 버튼 줄 고정), 필수 칸은 공통 빨간 안내(`base.html`의 invalid 처리)를 그대로 쓴다. 위험한 쓰기는 `btn--danger` + 이유 입력.
- 문구는 `docs/brand.md`: 짧은 '-요'체, 설명 문장은 최소. 판정 4단계 이름 그대로.
- 390px 폭에서 가로 넘침 없음(왼쪽 메뉴는 위 가로 탭으로 바뀜).

## 5. 테스트 (실제 위험 위주)

- 스태프 아닌 사용자·비로그인: 모든 `/admin` 경로 404(직접 URL 포함).
- 쓰기마다 감사 기록 1건, 이유 없으면 저장 안 함.
- 비활성화한 사용자의 기존 세션이 바로 끊긴다.
- 번호 가림 기본, '보기'는 감사 기록 남김.
- 지표 계산: 경계(보고 시각 = 요청 시각), 미응답 조치 제외, 대체된 조치 처리.
- 페이지 처리·쿼리 수 상한(목록 1페이지 쿼리 수 고정).

## 6. 순서 제안

A01 권한·감사 기록·개요 → A02 사용자·세션 → A03 현장·조정자 지정(`grant_site.py` 대체) → A04 수집·판정 상태 → A05 지표. 각 단계마다 `scripts/check.py` 통과 후 `main`.

## 7. 확인 필요(개발자)

- 운영자가 대화방·조치 본문을 볼 수 있는가(기본: 못 봄).
- 회사 병합 기능이 필요한가(기본: 안 함, 같은 이름 묶어 보기만).
- 스태프 2단계 인증(문자 인증 도입 뒤)을 필수로 할지.

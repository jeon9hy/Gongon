- S04-2: 설치 버전에 맞는 FastAPI·Starlette 공식 인증/세션 문서와 OWASP 공식 세션·CSRF 지침. 세션 만료·로그아웃·현장별 권한·폼 보호 설계에 필요한 절만 읽고 선택을 decisions.md에 기록한다.
- S04·S06: PostgreSQL·SQLAlchemy·Alembic 공식 문서의 트랜잭션·고유 제약·마이그레이션. 현재 구현을 먼저 읽고 동시 실행·실패 복구에 필요한 내용만 대조한다.
- S07: Render·Supabase·GitHub Actions 공식 운영/요금/예약 실행 문서. 계정 개설·배포 시 휴면·용량·예약 지연·비용을 다시 확인한다. 이전에 적힌 무료 조건을 현재 보장으로 쓰지 않는다.
- S08~S10: 총정리 §2.4·4.2 + 익명화된 실제 현장 일정 변경 사례. 작업·변경·공유·결과 필드를 사례에 대조한다. 현장 자료는 허락 없이 외부 서비스에 업로드하지 않는다.

- 추가 공종: 해당 작업 승인 후 국가건설기준센터의 KCS 원문·국가법령정보센터·장비 제조사 매뉴얼을 확보한다. 블로그 표나 다른 서비스의 판정값을 기준표에 옮기지 않는다.

## 수집·보관 절차

1. 해결할 질문을 먼저 적는다(예: PCP 시각이 어느 강수 구간을 뜻하는가). 문서 전체를 반복해서 읽지 않는다.
2. 공식 페이지에서 해당 버전의 문서/첨부를 확보한다. 페이지에 접근했어도 첨부를 못 받으면 미확보로 남긴다. 로그인이 필요하면 사용자가 공식 계정에서 내려받은 파일로 이어간다.
3. 필요한 절·표·페이지와 짧은 요약만 기록한다. 원본 파일을 보관할 때는 파일명·버전·해시·저장 위치·이용 조건을 남기고, 대용량 원문을 무조건 Git에 넣지 않는다.
4. 테스트 API 예시는 공식 예시 또는 실제 응답만 사용한다. 기존 `tests/engine/forecast/data/`, `tests/app/features/sites/data/`를 먼저 확인한다. 키·토큰·개인정보를 제거하고 구조·시각·값은 보존한다.
5. 법령 원문은 AI가 비교 자료를 준비하고 개발자가 최종 대조한다. 그전에는 `[원문 대조 필요]`를 유지한다. 모호한 내용은 plan.md의 해당 작업에 확인 항목으로 남긴다.

기록 형식: `작업 ID / 확인 질문 / 기관·문서명 / URL / 문서 버전·시행일 / 접근일 / 절·표·페이지 / 추출 사실 / 적용 코드·테스트 / 남은 확인`.
기준 버전은 접근일과 구분하고, 자료 갱신 시 영향받는 규칙·계약·테스트를 같은 작업에서 갱신한다.

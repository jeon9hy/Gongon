# 공온 판정 기록 계약 v1.0

`schema.json`은 저장된 판정 한 건을 `service.serialize_judgment()`로 변환한 JSON의 계약이다. DB의 hours·windows 형식은 유지한다. 새 API나 DB 테이블은 추가하지 않는다. `schema_version`은 표현 형식의 버전이며 법령/규칙의 `rule_version`과 다르다.

## 값의 의미
- `data_type=forecast`: 예보 기반 판정이다. 담당자 결정이나 실제 중단 기록으로 해석하지 않는다.
- 시각은 RFC 3339의 `+09:00`을 사용한다. DB가 UTC로 반환한 열은 KST로 변환하고 시간대 없는 입력은 거부한다. 날짜는 현지 날짜다.
- `element_units`는 각 요소의 lower·upper·threshold에 공통으로 적용한다. 원표현 `raw`는 기상청 표현을 보존한다.
- 원문 대조 전에는 `rule_source_verified=false`를 유지한다. 직렬화나 계약 검사 통과가 원문 검증을 뜻하지 않는다.
- 일부 요소 누락은 해당 조건의 raw·lower·upper가 모두 null이고 해당 조건은 `판정 불가`다. 다른 조건에 중지 검토가 있으면 기존 엔진의 단계 우선순위에 따라 전체 결과는 중지 검토일 수 있다.
- 값이 있을 때 upper=null은 상한 없는 범주다. 값 누락과 구분하려면 raw·lower를 함께 본다.
- 수집 실패는 failure_reason이 있고 forecast_issued_at=null, hours=[], 전체 작업 구간의 windows 한 건과 전체 판정이 `판정 불가`다. 발표본은 확보했지만 작업 구간 값이 누락된 경우와 구분한다.
- 직접 비교 불가는 해당 조건에 `확인 필요`와 사유를 남긴다. 기준 자체가 없는 공종은 DB 판정 기록을 생성하지 않는 기존 정책을 유지한다.

## 검사 범위
표준 검증기 `jsonschema.Draft202012Validator`와 `FormatChecker`를 사용한다. format 키워드만 선언하면 시각 검사가 실행되지 않으므로 rfc3339-validator를 개발 의존성으로 포함한다. 예시와 실제 DB 저장 기록을 오프라인 테스트에서 대조한다.

JSON Schema는 타입·필수 필드·추가 필드·판정·단위·시각 형식·실패/누락의 구조를 검사한다. 시각의 앞뒤 비교, 시간별 범위가 작업 구간을 빠짐없이 덮는지, 판정 계산의 타당성은 스키마만으로 검사하지 않는다. 이 의미 조건은 기존 현장 입력 검증·판정 엔진과 관련 테스트가 담당한다. 이 계약은 임의 외부 JSON을 DB에 넣는 입력 검증 API가 아니다.

현재 hours는 상한 포함 여부와 forecast_comparable을 별도 필드로 저장하지 않는다. 원표현·기준·판정 사유를 보존한 조회 계약이며, lower/upper만으로 판정을 재계산하면 안 된다. 재계산은 원자료와 당시 규칙을 사용해야 한다. 향후 독립적인 재판정용 계약이 필요하면 포함 여부·비교 가능성·원문 스냅샷의 보존 범위를 정하고 마이그레이션으로 변경한다. 과거 기록의 미확인 값을 추측해 채우지 않는다.

## 예시
`contract-examples.json`은 이름을 키로 한 다섯 기록이다. 각 값이 schema.json 검증 대상이다. **모두 계약 설명용 합성 데이터이며 기상청 실제 응답·현장 사례가 아니다.** `not_comparable`은 비교 불가 표현을 설명하려고 철골 예시의 조건을 가상으로 바꾼 것이며 실제 철골 기준을 수정한 것이 아니다.

| 이름 | 설명 |
| --- | --- |
| go | 기준 미만, 강수 미만 범주 보존 |
| stop | 강우 기준과 같은 값 |
| missing | 풍속 값 누락 |
| not_comparable | 가상 비교 불가 조건 |
| collection_failed | 예보 수집 실패 |

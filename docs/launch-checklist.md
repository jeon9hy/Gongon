# MVP 공유·출시 준비 목록 (2026-10-17)

개발자가 직접 만들거나 결정해야 하는 것만 모았다. 키·계정 값은 지어내지 않는다. 받은 값은 `.env`에만 넣는다(커밋 금지).

## 1. 내일 아침 MVP를 친구들에게 보내는 방법

지금 공온은 내 PC(127.0.0.1)에서만 열린다. 링크로 보내려면 둘 중 하나가 필요하다.

| 방법 | 준비 | 장단점 |
| --- | --- | --- |
| **임시 터널(추천, 오늘 바로)** | Cloudflare `cloudflared` 설치 → `cloudflared tunnel --url http://localhost:8000` | 계정 없이 `https://…trycloudflare.com` 주소가 나온다. 내 PC·서버가 켜져 있을 때만 열린다. 주소는 실행할 때마다 바뀐다 |
| 배포 | 서버(예: Render·Fly.io·AWS Lightsail) + 관리형 PostgreSQL + 도메인 | 늘 열려 있다. 비용·설정 필요 |

- 터널·배포 모두 HTTPS라 `.env`에 `SESSION_COOKIE_SECURE=1`을 넣고 재시작한다.
- 공유 전 확인: 시연 계정 `pm@demo.gongon.test` / `gongon-demo-1234`(조정자), 협력업체 `frame@demo.gongon.test`(담당자). 친구들은 가입해서 휴대폰 번호로 현장에 초대할 수 있다(문자 인증은 아직 없음).
- 가입이 열려 있다(D-014). 링크가 퍼지면 누구나 가입할 수 있으니 시연 뒤 터널을 끈다.

## 2. 필요한 외부 API·계정

| 무엇 | 어디서 | 쓰는 곳 | 상태 |
| --- | --- | --- | --- |
| 기상청 단기·중기예보 | 공공데이터포털 또는 기상청 API허브 | 공온 판정·공온지수 | **설정됨**(`KMA_SERVICE_KEY`/`KMA_APIHUB_KEY`) |
| 카카오 로컬(주소→좌표) | Kakao Developers 앱 REST 키 | 현장 위치 찾기 | 있으면 `KAKAO_REST_API_KEY`, 없으면 위경도 직접 입력 |
| 다음 우편번호 | 키 없음 | 주소 찾기 창 | 동작 중 |
| **공휴일(특일 정보)** | 공공데이터포털 '한국천문연구원 특일 정보' 활용 신청(무료, 일반 인증키) | 달력 공휴일 표시·작업일 계산 | 미구현. 키를 받으면 하루 한 번 받아 저장하는 어댑터를 붙인다. 대체공휴일·임시공휴일 때문에 고정 목록보다 API가 맞다 |
| **문자(SMS) 인증** | 문자 발송 업체 1곳(예: NHN Cloud SMS, 솔라피, 알리고) | 가입·초대 번호 인증 | 미구현. 계정 + **발신번호 사전 등록**(통신사 가입 증명 필요) + 건당 요금(업체별 확인). 개인 가입 가능 여부는 업체마다 다르다 |
| 카카오 알림톡 | 카카오 비즈니스 채널 + 발송 대행사 | 변경·조치 알림(C07) | 미구현(D-015). **사업자등록**·채널 개설·템플릿 사전 승인 필요 |
| 구글 로그인 | Google Cloud Console OAuth 클라이언트 | 소셜 로그인 | 보류(D-072). 배포 도메인(리다이렉트 주소)이 먼저 필요 |
| 네이버 로그인 | Naver Developers 애플리케이션 | 소셜 로그인 | 보류. 서비스 검수 필요 |
| 카카오 로그인 | Kakao Developers 앱(카카오 로그인 켜기) | 소셜 로그인 | 보류. 현장 사용자에게 가장 쓸모 있어 1순위 추천 |
| 서버·DB·도메인 | 호스팅·관리형 PostgreSQL·도메인 업체 | 상시 공개 | 미정(비용 결정 필요) |

## 3. 인증(로그인·본인 확인) 계획

지금: 이메일+비밀번호, 서버 세션(12시간, 해시 저장), 같은 출처 검사, 휴대폰 번호는 **인증 전**으로 저장(D-073). 로그인 시도 제한이 없다(D-014 남은 위험).

| 단계 | 내용 | 필요한 것 |
| --- | --- | --- |
| 1. 지금(MVP) | 이메일·비밀번호 가입, 번호로 현장 초대, 화면에 '인증 전' 표시 | 없음 |
| 2. 로그인 보호 | 이메일·IP별 시도 제한(예: 10분에 5회), 비밀번호 재설정 메일 | 메일 발송 계정(재설정용) |
| 3. 문자 인증 | 가입·번호 변경 때 6자리 코드(3분, 5회 제한, 번호·IP별 발송 제한, 코드는 해시 저장) → `phone_verified_at` 기록. 어댑터 경계에서 가짜 발송으로 테스트 | 문자 업체 계정·발신번호 |
| 4. 문자 초대 | 조정자가 번호로 초대하면 1회용 링크 문자 발송, 받은 사람이 가입하면 그 현장·업체에 자동 연결 | 3단계 + 배포 도메인 |
| 5. 소셜 로그인 | 카카오 → 네이버 → 구글 순. 같은 번호·이메일 계정과는 사람이 확인하고 연결(자동 병합 금지) | 각 개발자 콘솔 앱·키·도메인 |

인턴 회사 화면처럼 '인증번호 받기' + 약관 동의 구성은 3단계에서 만든다. 약관·개인정보처리방침 **원문**은 지어내지 않는다. 개발자가 문안을 정하거나 법률 검토를 받아야 한다.

## 4. 원청·하청 대신 '상단·중단·하단' 같은 현장별 위계 (개발자 질문)

- 지금은 업체 구분(원청·협력업체·자재 공급·장비 임대·감리)과 권한(조정자·담당자·열람자·게시)이 따로 있다(D-066). 직책은 자유 입력이다.
- 실제 현장은 '원청 → 1차 협력업체 → 2차(재하도급)'처럼 단계가 있다. 추천: 업체에 **상위 업체(누구 밑에서 일하는지)**를 하나 두고 화면에서 '1단·2단'으로 보이게 한다. 권한은 지금처럼 따로 둔다.
- 범위가 바뀌는 결정이라 개발자 확인 뒤 별도 작업으로 한다(현장 관계자 1~2명에게 실제 구조를 물어보면 좋다).
